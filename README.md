# Telegram-бот администрирования каналов и групп

Бот `@donabor_sol_bot` — пригласительные ссылки, поиск Account ID, глобальный бан.

## Возможности

- `/createlink <N>` — пригласительная ссылка с лимитом участников и выбором формата
- `/id <@username|ID>` — Account ID по юзернейму и наоборот; работает ответом на сообщение
- `/ban <@username|ID> [причина]` — бан пользователя во всех чатах, где есть бот
- `/unban <@username|ID>` — снять бан во всех чатах
- `/unmute <@username|ID>` — снять ограничение с новичка
- `/chats` — чаты, известные боту
- Автоматическая запись всех входящих в Google Таблицу (Account ID + username)

## Установка

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

## Настройка

Секреты передаются только через переменные окружения — в коде их нет.

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен от @BotFather |
| `SPREADSHEET_ID` | да | ID Google Таблицы |
| `GOOGLE_CREDENTIALS_FILE` | нет | Путь к ключу сервисного аккаунта (по умолчанию `/root/bot/231.json`) |
| `ADMIN_IDS` | нет | Telegram ID админов через запятую — кому разрешён глобальный бан |
| `CONFIRM_ON_JOIN` | нет | `1` — мут новичкам до нажатия кнопки, `0` — выключено |
| `MUTE_HOURS` | нет | Сколько держать мут, по умолчанию 24 |

### Google Таблица

Сервисный аккаунт из ключа должен иметь права **редактора** на таблицу.
Листы создаются автоматически: `Ссылки`, `Пользователи`, `Чаты`, `Баны`.

### Права бота

В каждой беседе нужны права администратора, минимум:
- «Блокировать участников» — для бана и мута
- «Приглашать по ссылке» — для `/createlink`

## Запуск

Unit-файл systemd: `deploy/bot.service`. Токен и настройки — в `Environment=` строках.

```bash
sudo cp deploy/bot.service /etc/systemd/system/bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now bot.service
journalctl -u bot.service -f
```

## Важно

Файл ключа сервисного аккаунта (`231.json`) и токен бота в репозиторий не попадают —
они перечислены в `.gitignore`. Не коммитьте их.
